# Coach Will

An iOS training coach. It reads health data and each morning gives one specific
session to do, with a readiness read. The product bet is that it **makes a call**
rather than showing a dashboard — every design and prompt decision follows from
that.

- Backend: FastAPI + Postgres on Fly (`jd-coach-api`, db `jd-coach-db`, region `ord`)
- iOS: SwiftUI. **`ios/project.yml` is the source of truth**; the `.xcodeproj` is
  generated by XcodeGen and gitignored. Never edit the project file.
- Repo: `assistjmd/coach` (private), working branch `fix/oauth-connect-flow`

## Working here

```bash
# tests — 479 of them, all should pass
cd backend && source .venv/bin/activate && python -m pytest tests/ -q

# deploy backend — fly.toml has release_command = "alembic upgrade head",
# so migrations run in a one-off machine before the new version takes traffic.
# A failed migration aborts the deploy instead of leaving a mismatched schema.
cd backend && fly deploy --now

# iOS build
cd ios && xcodegen generate && xcodebuild -project Coach.xcodeproj \
  -scheme Coach -configuration Release -destination 'generic/platform=iOS' build

# ship a TestFlight build: bump CURRENT_PROJECT_VERSION in project.yml, then
# archive → export → altool upload, then:
python3 tools/testflight.py ship --notes-file notes.txt
python3 tools/testflight.py status

# product metrics — counts only, never message content
python3 tools/metrics.py
```

`tools/asc.py` is a minimal App Store Connect client (`GET|POST|PATCH <path> [json]`).
It needs `~/.appstoreconnect/private_keys/AuthKey_55WY75228U.p8`, which is **not
in the repo and never should be**. Without it, nothing in `tools/` works — that
is the main thing a session on another machine cannot do.

`backend/.env` is likewise local-only. Production config lives in `fly secrets`.

## Rules that came from real bugs

Each of these was a shipped defect. They are not style preferences.

**Calendar days belong to the athlete, not the server.** Fly runs UTC, so
`date.today()` rolls over at 7pm in Boston. Everything goes through
`app/dates.py` — `today_for(user)`, `local_day(dt, tz)`. Timestamps sent to the
model are converted to the athlete's zone too, or the coach describes a 10pm
Tuesday session as "early this morning".

**One session arrives from many sources.** Strava's API, plus separate HealthKit
records written by Garmin Connect, the Strava app and the Watch — four different
UUIDs for one workout. `analytics/dedupe.py` collapses on time overlap, keeps the
record carrying more signal (heart rate outranks provenance, because HR decides
TRIMP versus a duration estimate), and retains `contributing_sources`. Adjacency
is deliberately *not* merged: a brick session is a bike then a run.

**Sleep is not one record.** Apple Health stores a night as dozens of stage
fragments, delivered across syncs. `analytics/sleep_repair.py` merges them, with
three different rules: different sources never merge, same-source overlapping
takes the *max* of each stage, same-source adjacent *sums*. A physical backstop
clamps time-asleep to time-in-bed.

**Provider caps are the reason Apple Health leads.** Strava stops an unreviewed
app at 10 connected athletes, Oura at 10 users, Google Health at 100. Direct
connections are gated per-provider by `DIRECT_PROVIDERS` (a comma-separated list
of slugs). Closing new connections must not break existing ones — `get_provider`
governs what is *offered*, `get_sync_provider` moves data for tokens that already
exist. Conflating them broke every live connection for a day.

**Model replies are not guaranteed to be JSON.** Both `ai/brief.py` and
`ai/adjust.py` guard the parse. A prose refusal used to surface as HTTP 500.

**Guardrails generalise further than intended.** A rule meant to stop someone
piling work onto a low-readiness day refused six of nine real "add strength
training" requests. Prompt constraints need testing against actual usage, not
just reasoning.

**A list is something a model reads past.** Ten days of prior sessions were in
the context and the coach still prescribed the same run fourteen days running.
`analytics/variety.py` counts instead, so `most_repeated: easy run × 13` cannot
be skimmed.

## Money and safety

- Every model call is metered. Chat and session-adjustment draw on **separate**
  allowances (`chat_daily_message_limit`, `adjust_daily_limit`) — sharing one
  meant a chatty day left someone unable to fix their workout.
- Brief refreshes are capped at `MAX_REVISIONS` per day.
- Entitlement is decided **server-side only**, from Apple's signature over the
  transaction (`subscriptions/apple.py`). The client reports; the server decides.
- `subscriptions_enforced` gates the paywall. Reading history, exporting data and
  deleting an account stay open regardless — the privacy policy's promises do not
  pause when a subscription lapses.

## Voice

The coach's persona lives in `ai/prompts.py`. The NEVER list there is long and
specific because describing a tone does not move a model off assistant cadence —
naming the constructions to avoid does. Do not soften it.

Interface copy follows the same register: sentence case, no exclamation marks, no
praise. State the fact. `"8 of 10 sessions done"`, never `"Great job!"`.

Never put health data in a notification body — a lock screen is readable by
whoever is standing nearby.

## Design

Full system: `docs/design.md` if present, otherwise the tokens in
`ios/App/Design/Theme.swift` are authoritative. Direction is Oura-leaning calm
with exactly **one bold element per screen** — the readiness number. Panels have
no border; space separates them. Numbers are always tabular. `WillMark` (a 270°
arc, the readiness ring shrunk) appears beside anything the coach wrote and
nowhere else.

## Current state

- TestFlight: build 29, public link `https://testflight.apple.com/join/rdSWG9GH`
- App Store: 1.0 assembled and staged in a review submission, **not yet
  submitted**. Free app, subscriptions at $12.99/mo and $99/yr.
- `subscriptions_enforced` is **false** — nobody is gated yet.
- Live direct provider: Google Health only. Oura, Strava, Garmin, Wahoo are
  announced rows that route through Apple Health.
- Wahoo is built and tested but has no credentials; it goes live by setting
  `WAHOO_CLIENT_ID` / `WAHOO_CLIENT_SECRET` and adding `wahoo` to
  `DIRECT_PROVIDERS`.

## What is still open

- Testers have given almost no feedback on whether the daily call is any *good*.
  That is the only question that decides whether this works, and it is unanswered.
- Data export endpoint exists; a UI for it is in the Goal tab.
- No analytics SDK, deliberately. The App Privacy labels declare zero tracking,
  which is a real differentiator — adding one destroys it permanently.
